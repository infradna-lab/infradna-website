# 연구 성과 페이지 · 수행 과제 홍보 페이지 설계

- 날짜: 2026-07-18
- 상태: 설계 확정 (구현 계획 대기)
- 관련: `src/data/projects.ts`, `src/pages/`, `src/components/`

## 1. 개요

기존 단일 페이지 사이트에 **독립된 두 페이지**를 추가한다. 두 페이지는 독자와
목적, 그리고 보유 자료의 형태가 서로 달라 구성 원리가 갈린다.

| | 연구 성과 페이지 | 수행 과제 홍보 페이지 |
|---|---|---|
| 성격 | 회고적 · 사진 아카이브 · "보여준다" | 전망적 · 내러티브 · "설득한다" |
| 보유 자료 | 분류 정보 없는 이미지 뭉치 | 5장짜리 PPT 1개 (구조화된 텍스트+지표) |
| 본문 방식 | 심플 반응형 그리드 + 라이트박스 | **PPT 내용을 반응형 HTML로 재구성** |

공통 목적은 **대외 홍보(PR)**이며, 주 독자는 **① 미디어·일반 대중**과
**③ 잠재 협력·후원 기관** 두 층이다. 그래서 두 페이지 모두 히어로의 임팩트
메시지(①용)와 협력/문의 CTA(③용)를 공유한다.

## 2. 핵심 설계 결정과 근거

### 결정 1 — 성과 페이지는 "필터형"이 아니라 "심플 그리드"
보유 사진에 촬영일·행사명·분류 같은 **메타데이터가 없다.** 필터/카테고리
UI를 만들려면 사진마다 수작업 태깅이 선행돼야 하므로 현 시점엔 과하다.
자료를 그대로 올릴 수 있는 **심플 반응형 그리드 + 라이트박스**로 출발하고,
구조가 필요하면 **배열 순서 기반 수동 그룹핑**(소제목 몇 개)으로 나중에
고도화한다.

### 결정 2 — 홍보 페이지는 슬라이드 이미지/PDF 임베드가 아니라 HTML 재구성
검토 결과(부록 A) PPT는 5장이며 **재난 테마별로 `문제 → 우리의 해결 →
핵심 지표 3개`라는 규칙적 구조**로 이미 짜여 있다. 다음 이유로 이미지·PDF
임베드가 아닌 **반응형 HTML 재구성**을 택한다.

- **모바일 가독성**: 슬라이드는 16:9 가로 고정 캔버스다. 페이지의 알맹이인
  작은 숫자·수식(`r=0.59 (p<0.001, n=70)`, `V=0.4CE+0.3ST−0.3AC`)이 통짜
  이미지로는 모바일에서 뭉개진다. 이미지는 리플로우되지 않기 때문. 이 사이트의
  홍보 대상은 **PC와 모바일 양쪽**이므로 치명적이다.
- **재구성 비용이 낮음**: 5장 + 규칙적 구조라 재작성 부담이 작다.
- **디자인 일체화**: 사이트의 네이비(`#1e3a5f`)·시안(`#0891b2`)·`break-keep`
  체계와 완전히 한 몸이 되어 "디자인 안 해치고 최적화"를 실제로 달성한다.
- **원본은 보존**: 원본 PPT를 PDF로 변환해 **다운로드 버튼**으로 제공한다.

부수적으로, PPT 원본은 아직 완성본이 아니다(각 슬라이드에 `이미지추가`
자리표시자 존재). 이미지로 굽지 않는 편이 향후 자료 교체에도 유리하다.

## 3. 페이지 A — 연구 성과

라우트: `/achievements`

구성(위→아래):

1. **히어로** — 임팩트 한 줄 + 앵커 지표 2~3개(예: 수행 과제 N건 · 협력기관 N ·
   교육 수료 N명). 사진이 주인공이어도 숫자 몇 개가 신뢰를 잡아준다.
   지표 값은 실제 확보 후 채운다(§8 열린 항목).
2. **성과 갤러리** (핵심) — 심플 반응형 그리드. 클릭 시 라이트박스로 확대.
   - 캡션은 **있는 것만 선택적으로**. 없으면 비워도 그리드는 성립한다.
   - 배열을 몇 덩어리로 나눠 소제목을 얹는 **수동 그룹핑은 선택**(초기엔 단일 그리드로도 무방).
3. **협력·문의 CTA** — ③ 독자용 연결 고리(기관 연락처/문의 유도).

데이터: `src/data/gallery.ts` (신규). §6 참조.

## 4. 페이지 B — 수행 과제 홍보

라우트: `/research`

구성(위→아래):

1. **히어로(표지)** — PPT 표지에 대응. "실측 데이터로 짚어내는 폭염·한파·홍수·가뭄
   대응 연구" 류의 한 줄 + 부제. 4대 재난을 아이콘/이름으로 예고.
2. **재난 테마 블록 × 4** (폭염 / 한파 / 홍수·침수 / 가뭄) — 각 블록은:
   - 영문 eyebrow(`HEAT WAVE`) + 재난명 제목 + 한 줄 요약
   - **문제**(이 재난 대응의 공백) / **우리의 해결**(접근·방법)
   - **핵심 지표 카드 3개** — `값 + 라벨 + 캡션` (예: `r=0.59` / "위성·실측 상관" /
     "p<0.001, n=70, 30m LST vs IoT")
   - **도표 자리(figures)** — 연구 그림이 들어갈 반응형 프레임(초기엔 placeholder,
     PPT의 `이미지추가` 자리에 해당)
3. **원본 자료 다운로드** — 변환한 PDF 다운로드 버튼.
4. **협력·참여 CTA**.

데이터: `src/data/researchThemes.ts` (신규). §6 참조.

반응형 규칙: PC는 지표 카드 3열·본문 2단 등 넓게, 모바일은 1열 세로 스택으로
자연스럽게 흐른다. 모든 텍스트·숫자는 리플로우된다(이미지로 굽지 않는다).

## 5. 공유 UI 컴포넌트

두 페이지가 부품을 공유하도록 설계한다(격리·단일 책임).

- `PageHero` — 네이비 히어로. props: 제목, 부제, 선택적 앵커 지표 배열.
- `ImageGrid` — 반응형 이미지 그리드(성과 갤러리 본체).
- `Lightbox` — 클릭 확대 오버레이(그리드·도표 공용). 키보드 esc/←/→, 모바일 스와이프.
- `MetricCard` — `값 + 라벨 + 캡션` 지표 카드(홍보 지표, 히어로 앵커 지표 공용).
- `CtaSection` — 협력·문의 CTA(두 페이지 공용, 문구만 주입).
- 기존 `FooterSection` 재사용.

애니메이션은 기존 관례대로 `framer-motion`(`'framer-motion'`에서 import).

## 6. 데이터 모델 (신규 소스, 기존 `projects.ts`와 분리)

```ts
// src/data/gallery.ts
export interface GalleryItem {
  src: string;        // '/gallery/xxx.webp' (public/ 기준)
  alt: string;        // 접근성/대체텍스트
  caption?: string;   // 선택
  group?: string;     // 선택, 수동 그룹핑용 소제목 키
}
export const galleryItems: GalleryItem[];
export const achievementStats: { value: string; label: string }[]; // 히어로 앵커 지표

// src/data/researchThemes.ts
export interface Metric { value: string; label: string; caption?: string; }
export interface ResearchTheme {
  id: string;          // 'heatwave' | 'coldwave' | 'flood' | 'drought'
  eyebrowEN: string;   // 'HEAT WAVE'
  disaster: string;    // '폭염'
  title: string;       // '과천시 지표면 온도로 찾아낸 폭염 취약지역'
  summary: string;     // 한 줄 요약
  problem: string;     // 문제
  solution: string;    // 우리의 해결
  metrics: Metric[];   // 보통 3개
  figures: { src: string; alt: string }[]; // 초기 빈 배열 허용(placeholder)
}
export const researchThemes: ResearchTheme[];
export const researchIntro: { title: string; subtitle: string };
```

## 7. 라우팅 / 진입점

- `App.tsx`에 라우트 2개 추가: `/achievements` → `AchievementsPage`,
  `/research` → `ResearchPage`. 기존 `/`, `/projects/:id`는 그대로.
- `ScrollManager`는 신규 라우트에도 그대로 적용(해시 없으면 최상단).
- **진입점**: 홈에서 두 페이지로 가는 링크를 추가한다(헤더 내비 또는 관련
  섹션 하단 링크). 정확한 위치는 구현 계획에서 확정.
- 정적 호스팅 SPA 폴백은 기존 `vercel.json` rewrite가 이미 커버한다.

## 8. 콘텐츠 소스 & 자산 처리

- **성과 사진**: 원본 이미지를 웹 최적화(webp, 적정 해상도)해 `public/gallery/`에
  넣고 `gallery.ts`에서 참조. 원본 뭉치 → 최적화 변환 절차는 구현 계획에 포함.
- **홍보 도표(figures)**: PPT의 `이미지추가` 자리에 들어갈 연구 그림. 확보 전까지
  `figures: []`로 두고 프레임은 placeholder 렌더.
- **PDF 다운로드**: 원본 PPT → PDF 변환본을 `public/`에 두고 홍보 페이지에서 링크.
- **가뭄(슬라이드 5) 텍스트**: 원본에서 텍스트가 이미지로 구워져 있어 자동
  추출 불가. 해당 문제/해결/지표 문구는 **사용자에게 별도로 받아** 채운다.

## 9. 디자인 / 반응형 규칙

- 색·간격·타이포는 기존 컴포넌트 관례를 따른다: 네이비 `#1e3a5f`, 시안
  `#0891b2`, 중립 `slate-*`, 한글 `break-keep`, `container mx-auto` 레이아웃.
- Tailwind v4 유틸 + 임의값 방식 유지(현재 `tailwind.config.js`는 미로드 —
  CLAUDE.md 참조). 새 토큰/테마 도입은 이번 범위 밖.
- 접근성: 모든 이미지 `alt`, 라이트박스 키보드 조작, 대비 준수.
