# session-log — 프로젝트 컨텍스트 문서 갱신

이 스킬은 `docs/PROJECT_CONTEXT.md`(프로젝트의 단일 기억 문서)를 이번 세션 내용으로 보완한다.

## 절차

1. **현재 문서를 읽는다** — `docs/PROJECT_CONTEXT.md`. (SessionStart 훅으로 이미 컨텍스트에 있을 수 있으나, 편집 전 최신 상태를 확인한다.)
2. **로컬 원장 확인** — `.claude/session-ledger.local.md` 가 있으면, 아직 문서에 반영되지 않은 지난 세션 흔적이다. 함께 정리한다.
3. **이번 세션에서 반영할 것을 추린다**:
   - 새로 내린 **결정**과 그 **이유** (무엇을 왜 그렇게 정했는가)
   - 아키텍처/데이터/스타일/배포 관련 **변경**
   - 새로 드러난 **함정·컨벤션**
   - 완료했거나 새로 생긴 **TODO**
   - 바뀐 **기관 사실**(연락처·명칭 등)
4. **문서를 갱신한다**:
   - 지속적 사실은 해당 섹션(2~5)에 **중복 없이 병합**한다. 기존 서술이 틀렸으면 고치고, 겹치면 갱신한다(새 항목을 무작정 덧붙이지 말 것).
   - 완료된 TODO는 "열린 항목"에서 제거하거나 체크 표시한다.
   - **세션 로그(6번)**에 오늘 날짜로 항목을 하나 추가한다(최신이 위로). 주요 커밋 해시가 있으면 함께 남긴다. 날짜는 세션 컨텍스트에 주어진 "Today's date"를 사용한다.
5. **간결성 유지** — 문서는 다음 세션에 매번 주입되므로 짧고 정확해야 한다. 세션 로그가 너무 길어지면 오래된 항목을 요약·압축한다. 코드에서 자명한 내용(파일 구조 등)은 굳이 적지 않는다.
6. **원장 비우기** — 문서에 반영을 마쳤으면 `.claude/session-ledger.local.md` 를 비운다(파일 삭제 또는 내용 제거).
7. 문서 변경은 다른 코드 변경과 함께, 또는 단독으로 커밋한다. **사용자가 요청할 때만** 커밋/푸시한다.

## 원칙

- 이 문서는 "무엇을 했는가"보다 **"무엇을 왜 그렇게 정했는가"**를 남기는 것이 핵심이다(코드/깃 로그로 알 수 있는 건 최소화).
- 추측을 사실처럼 적지 않는다. 미확정은 "열린 항목"에 둔다.
